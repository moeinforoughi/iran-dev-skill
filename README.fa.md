# Iran Dev Environment — اسکیل ایجنت برنامه‌نویسی (نسخهٔ 0.1.1)

این پروژه یک **Agent Skill قابل‌حمل** است که به Coding Agent کمک می‌کند روی اینترنت ایران علت خطای دسترسی را پیدا کند و توسعه را با میرورهای بررسی‌شده، تغییرات برگشت‌پذیر و روش‌های آفلاین ادامه دهد.

## داخل بسته چیست؟

- `SKILL.md`: دستورالعمل اصلی رفتار ایجنت و ترتیب تصمیم‌گیری.
- `references/diagnostic-playbook.md`: تشخیص خطاهای DNS، TCP، TLS، HTTP، API و دانلود.
- `references/mirror-catalog.yaml`: فهرست اولیهٔ میرورهای کاندیدا؛ هیچ موردی بدون تست روی اینترنت واقعی سالم فرض نشده است.
- `references/tool-inventory.yaml`: فهرست ماشینی ۵۳ ابزار و نسخه‌ای که در فهرست اولیه داده شده بود؛ نسخه‌ها مستقل تأیید نشده‌اند.
- `references/anti-censorship-tools.md`: دسته‌بندی ابزارها، روش بررسی پروژه‌ها و احتیاط‌های امنیتی.
- `references/service-access.md`: تفکیک خطای شبکه از محدودیت منطقه‌ای، حساب کاربری، دسترسی API و سهمیه.
- `references/service-catalog.yaml`: فهرست دامنه‌ها و مستندات/صفحهٔ وضعیت رسمی برای مخزن‌ها و APIهای مهم؛ این فهرست وضعیت زنده را تضمین نمی‌کند.
- `references/offline-first.md`: کش وابستگی‌ها، دانلود قابل‌ادامه، Git bundle و بیلد آفلاین.
- `references/security-and-trust.md`: امنیت میرورها، فایل‌های دانلودشده، بات‌های تلگرام و اطلاعات محرمانه.
- `references/source-policy.md`: تاریخ انقضا، سطح اطمینان و روش برخورد با گزارش‌های جامعه.
- `scripts/quick-diagnose.sh`: تست فقط‌خواندنی HTTPS با هدف/پروفایل انتخابی؛ به‌صورت پیش‌فرض همهٔ مقصدها را تست نمی‌کند و تنظیمات سیستم را تغییر نمی‌دهد.
- `templates/diagnostic-report.md`: قالب ثبت نتیجهٔ عیب‌یابی.
- `scripts/validate-project.sh`: بررسی ساختاری آفلاین برای نگه‌دارندگان؛ درخواست شبکه ارسال نمی‌کند.
- `scripts/check-governance-update.sh`: کنترل CI برای اجباری‌کردن ثبت تغییرات در `governance/WORK_LOG.md`.
- `AGENTS.md` و `governance/`: منشور پروژه، معماری، تسک‌ها، قواعد مشارکت، تاریخچهٔ تغییرات و محدودیت مصرف توکن/تست شبکه.

## ثبت اجباری تغییرات

در Pull Request، CI بررسی می‌کند که همراه هر تغییر، فایل `governance/WORK_LOG.md` هم به‌روز شده باشد. قالب Pull Request همچنین شواهد آزمون، تعداد probeهای شبکه، توجیه بهینه‌سازی و محدودیت‌های باقی‌مانده را مطالبه می‌کند.

## بررسی ساختاری پیش از مشارکت

پیش از ارسال تغییرات اجرا کنید: `bash scripts/validate-project.sh`. این آزمون لینک‌های محلی Markdown، فایل‌های لازم، frontmatter، نحو Bash و YAML (در صورت وجود PyYAML) را بررسی می‌کند. موفقیت آن به معنی سالم بودن زندهٔ میرورها یا VPNها نیست.

## راهنمای ایجنت‌های توسعه‌دهنده

پیش از هر تغییر، `AGENTS.md` و `governance/CONTRIBUTING.md` را رعایت کنید. هدف‌ها و محدوده در `governance/PROJECT_CHARTER.fa.md`، وضعیت کارها در `governance/TASKS.md` و ساختار فعلی در `governance/ARCHITECTURE.md` ثبت شده‌اند. هر کار باید در `governance/WORK_LOG.md` ثبت شود.

برای جلوگیری از مصرف بیهودهٔ توکن و پهنای باند، هر بار همهٔ فایل‌های مرجع را نخوانید. در کار عادی حداکثر ۱ تا ۲ مرجع مرتبط کافی است؛ عیب‌یابی عادی حداکثر ۳ مقصد خارجی را بررسی می‌کند. اسکریپت حالا نیازمند انتخاب صریح است، مثلاً:

```bash
./scripts/quick-diagnose.sh --profile python
./scripts/quick-diagnose.sh --profile docker
./scripts/quick-diagnose.sh --url https://host.example/path
```

فقط برای بررسی پایهٔ گسترده و با اجازهٔ کاربر اجرا کنید: `./scripts/quick-diagnose.sh --profile all`.

## اصل مهم طراحی

این پروژه قرار نیست تمام ابزارهای موجود را دوباره بسازد. نقش اصلی آن **لایهٔ دانش و تصمیم‌گیری ایجنت** است: تشخیص علت، انتخاب روش کم‌ریسک، آزمایش میرور و ثبت شواهد زمان‌دار. هر ابزار موجودی که کارش را خوب انجام می‌دهد، بهتر است بررسی و یکپارچه شود، نه اینکه از صفر بازنویسی شود.

## محدودیت نسخهٔ اولیه

این نسخه یک شروع قابل‌استفاده است، نه فید زندهٔ وضعیت اینترنت. میرورها، نسخهٔ اپ‌ها، IPها، پروتکل‌های قابل‌اتصال و وضعیت APIها متغیرند. فهرست‌ها صرفاً کاندیدا هستند و پیش از پیشنهاد باید از همان ISP/شبکه آزمایش شوند.

## مسیر توسعه

- **0.1:** ساختار استاندارد Skill، راهنمای عیب‌یابی، فهرست میرورها و ابزارها، روش‌های آفلاین و تست فقط‌خواندنی.
- **بهبود نگه‌داری:** قواعد ایجنت، منشور، معماری، لاگ تغییرات، تسک‌ها و سیاست محدودیت توکن/تست اضافه شدند؛ تست شبکه به هدف انتخابی محدود شده است.
- **0.2:** تست خودکار سلامت میرورها به تفکیک اکوسیستم و ذخیرهٔ نتایج همراه timestamp، ISP/network scope، TLS، latency، status و expiry.
- **0.3:** دستورالعمل‌های جداگانه برای Linux، Windows/WSL، macOS، Android/Termux و تنظیمات قابل‌بازگشت package managerها.
- **0.4:** ابزار CLI یا MCP اختیاری برای ارائهٔ تشخیص و دادهٔ زمان‌دار به ایجنت؛ هستهٔ پروژه باید بدون سرور هم مفید بماند.
- **1.0:** فرایند مشارکت، بازبینی منابع، بررسی امنیت، آزمون‌های تکرارپذیر و امضای انتشار.

## استفادهٔ اولیه

پوشهٔ `iran-dev-environment` را در مسیر اسکیل‌های ایجنت سازگار قرار بده و نام پوشه را با مقدار `name` در `SKILL.md` یکسان نگه دار. بعد از ایجنت بخواه ابتدا خطا را تشخیص دهد و قبل از تغییر تنظیمات، علت و اثر تغییر را توضیح دهد.
